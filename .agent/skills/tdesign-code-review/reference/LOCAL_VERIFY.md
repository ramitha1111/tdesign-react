# Bug Fix 本地验证

## 1. 拉取 PR 引用

```bash
N=<PR编号>

git fetch origin develop "pull/${N}/head:pr-${N}"
```

本地分支名：**`pr-<N>`**（§1 与 SKILL §2 的 diff 可并行，均依赖此次 `fetch`）。

---

## 2. 检查工作区

```bash
git status --porcelain
```

如果工作区干净后，则**记录审查前分支**。

如果存在未提交变更，**停止切换分支**，并执行 `AskQuestion`：

| 选项           | 操作                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| **stash**      | 执行 `git stash push -u -m "cr: PR #<N> review"`                               |
| **commit**     | 分析变更，生成 Commit Message，执行 `git add` 和 `git commit`。                |
| **仅静态审查** | 仅执行 SKILL §2 规定的静态审查，跳过分支切换和后续验证流程，直接输出审查报告。 |
| **其它**       | 根据用户明确指定的操作执行。                                                   |

流程结束后，继续执行下一步。

## 3. 切换与同步 develop 分支

```bash
git fetch origin develop
git switch develop
git pull --ff-only origin develop
```

`pull --ff-only` 失败时，执行 `AskQuestion`，禁止自动 `merge`。

## 4. 落地测试文件

**前提**：当前在 `develop` 分支，生产代码与远端一致；仅允许改动 `TEST_PATH` 对应文件。

| 来源    | `TEST_PATH`              | 操作                                               |
| ------- | ------------------------ | -------------------------------------------------- |
| PR 测试 | SKILL §2                 | `git show "pr-${N}:${TEST_PATH}" > "${TEST_PATH}"` |
| 无测试  | `review-pr-<N>.test.tsx` | 在对应 `__tests__/` 新建                           |

## 5. 验证缺陷

### 5.1 develop 分支

```bash
pnpm exec vitest run <TEST_PATH>
```

| 结果 | 判定与处理                                                             |
| ---- | ---------------------------------------------------------------------- |
| 失败 | 确认失败原因与 PR 描述的缺陷一致，继续执行 §5.2                        |
| 通过 | 判定为未复现，检查测试用例是否充分覆盖缺陷触发条件，修改用例并重新执行 |

**修改用例后仍无法复现，则将该 PR 标记为无法复现，停止审查**。

### 5.2 PR 分支

```bash
git switch "pr-${N}"
pnpm exec vitest run <TEST_PATH>
```

| 结果     | 判定与处理                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------- |
| **通过** | 修复验证通过，结合 §5.1 结果确定审查报告                                                            |
| **失败** | 修复验证未通过，禁止合并。结合 §2 Diff 与测试失败堆栈定位问题，并在代码建议中列出具体问题及修改建议 |

## 6. 恢复审查前状态

```bash
git switch <审查前分支>      # 切回 §2 记录的审查前分支
rm -f <review-pr 及 git show 产生的新文件>
git restore "${TEST_PATH}"   # 若 §4 覆盖过已跟踪文件
```

不得提交审查用测试。
